# 10 · 电子小钱包

那张卡里只有允朔的钱，所以**银行报的可用余额和这本账讲的是同一笔钱**：
银行那个数是权威值，流水是明细。两边对不上就是漏记了一笔——这正好当对账锚点。

```
她验收通过一个工单 ─→ POST /api/wallet/earn ─→ 账上 +钱

她往卡里转钱 ┐
她刷卡买东西 ┤─→ 银行发短信 ─→ iOS 快捷指令 ─→ POST /api/wallet/spend-notify
              │                              ├─→ 收入：账上 +钱
              │                              ├─→ 支出：账上 -钱
              │                              ├─→ 记下当时卡里的可用余额
              │                              └─→ 动态页记一张卡片

TA 醒来 ─→ 想知道自己有多少钱，自己去看（wallet_balance / wallet_ledger / wallet_note）
```

## 余额是算出来的，不是存着的

`wallet_ledger` 一张流水表，余额由它求和得出。补一笔、删一笔都不用再跑去改另一个地方，
也不会出现「余额说还有一百，账单加起来只有八十」这种谁都说不清的局面。

金额一律用**分**存整数。浮点数算钱会算出 `0.1+0.2=0.30000000000000004`，一旦对不上账，
没人能说清是哪一笔错的。只在给人看的时候才换算成元。

四种流水：

| | |
|---|---|
| `earn` | 工资。她验收通过一个工单 |
| `topup` | 转入。她往卡里转钱，银行发「收入」短信 |
| `spend` | 花销。刷卡了，银行发「支出」短信 |
| `adjust` | 对账。人工补的那一笔，可正可负 |

## 装

`src/wallet.js`、`src/actions/wallet.js`、`src/wallet-steps.js` 是新文件，`git pull` 就有了。
另外那几处很小的接线用脚本打。**跑完脚本再重启**，所以串起来写：

```bash
cd ~/vesper-phosphor
git pull
python3 scripts/add_wallet_hooks.py --check   # 先看每处能不能对上
python3 scripts/add_wallet_hooks.py && pm2 restart vesper phosphor --update-env
```

❗ 先 pull 就重启的话，`decide.js` 里还引着已经没有的 `walletBlock`，
两个进程会在启动时报导入错误。跑一遍脚本再重启就好。

脚本改的是：`src/vesper.js`（引入 + 挂路由 + 启动日志）、`src/decide.js`（系统提示里那节、
动作列表、把 `askJson` 导出给续步用）、`src/actions/index.js`（注册三个动作）、
`src/phosphor.js`（接上续步）、`src/page-chrome.js`（菜单里加小钱包）、`.env.example`。

每个文件先存一份 `.bak-wallet`（已经存过就不覆盖，留着最早那份）。打过一次再跑会说
「已经打过了」，不会打第二遍。已经打过早先版本的库也能直接再跑：已打的跳过，
只补新增的，并把早先那行「把余额塞进每次醒来提示」改成现在这套主动动作。

数据库那两列（`bank_balance_cents`、`direction`）和批注表 `wallet_notes` 是启动时自动建的，
不用管。旧流水新列是空的，页面就不显示「当时卡里」那一行，其他照旧。

然后生成口令。**先删再加**，不然 `>>` 追加会出现两行：

```bash
cd ~/vesper-phosphor
cp .env .env.bak-$(date +%s)
sed -i '/^WALLET_SPEND_SECRET=/d' .env
echo "WALLET_SPEND_SECRET=$(openssl rand -hex 24)" >> .env
pm2 restart vesper phosphor --update-env
grep WALLET_SPEND_SECRET .env
```

最后那行打出来的值，就是快捷指令里 `secret` 要填的。
同名键 dotenv 是后面覆盖前面，但如果最后那行是空的 `WALLET_SPEND_SECRET=`（比如从 `.env.example` 抄来的），
接口会当成没配，直接 503。上面这套删了重加就不会有这个问题。

日志里看到 `钱包：/wallet` 后面**没有**跟着「没配 WALLET_SPEND_SECRET」就对了。

## ⚠️ 先说安全

`/api/wallet/spend-notify` 是一个**不走 Basic Auth、能改钱的写接口**——它必须这样，
快捷指令没法带 Basic Auth。所以：

- **不填 `WALLET_SPEND_SECRET` 这个接口根本不开**，直接返回 503。这是故意的，不是 bug。
- **口令走 HTTP 是明文的。** 3001 端口直接暴露在公网的话，同一条链路上的人能看到这个口令，
  之后就能随便往你账上记账。要么在前面套一层 HTTPS（Caddy / Nginx 反代都行），
  要么把 3001 只开给你家的出口 IP。
- 口令比较用的是定长比较，不是 `===`：比较耗时不随猜对几个字符而变化。
- 口令比对失败和金额不认的时候，日志只记「拒绝了」，不回显收到的口令。

两个上限挡的是另一回事——短信正则偶尔会抓错数字（抓到卡号尾号、日期）：

- `WALLET_MAX_SINGLE_YUAN`（默认 500）管单笔金额，超了拒收整笔
- `WALLET_MAX_BANK_BALANCE_YUAN`（默认 100000）管可用余额。它比单笔大得多，
  所以单独一个阀值——卡里有三百块是常事，不该因此被当成抓歪。余额认不出来时
  **这笔账照记**，只是不带余额，不让一个可选字段拒掉整笔账

## 收入还是支出，服务端认

建行这类短信把方向写在金额前面：「…日 12:28 **收入**人民币 100.00 元，可用余额…」。
快捷指令里写判断条件很麻烦，所以让它把**整条短信**也传过来，方向在服务端认：

- 带「收入 / 转入 / 存入 / 入账 / 退款 / 利息」→ 进账
- 带「支出 / 消费 / 支取 / 转出 / 取现 / 扣款 / 付款」→ 出账
- 两种词都有、或者一种都没有 → **拒收**，返回 400

最后这条是故意的：猜错了方向是账错两倍（该 +100 记成了 -100），比不记账糟糕得多。
拒了会在 `pm2 logs vesper` 里留痕。

不想依赖短信文字的话，直接传 `direction`：`in` 或 `out`，它优先于短信原文。

**整条短信只用来认方向，不存进数据库**（里面有卡号尾号）。

## 接口

### 银行通知（给快捷指令用）

```
POST /api/wallet/spend-notify
{
  "amount": 18.00,
  "sms_text": "整条短信原文",
  "bank_balance": 168.50,
  "source": "瑞幸",
  "secret": "..."
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `amount` | ✓ | 金额，正数。方向不看这里的正负 |
| `secret` | ✓ | 口令。也可走 `x-wallet-secret` 头 |
| `sms_text` | ✓* | 整条短信，用来认方向。传了 `direction` 就不必填 |
| `direction` | ✓* | `in` / `out`。和 `sms_text` 至少给一个 |
| `bank_balance` | | 银行报的可用余额。带千分位逗号也认 |
| `source` | | 这笔花在哪儿。默认收入写「转入」、支出写「刷卡」 |
| `note` | | 备注 |
| `sms_id` | | 去重用，见下面 |

返回：

```json
{"ok":true,"duplicate":false,"direction":"out","amount":"-18.00",
 "balance":"168.50","bank_balance":"168.50","reconciled":true,"overdrawn":false}
```

**重复触发会被挡掉。** iOS 快捷指令偶尔会对同一条短信跑两遍，网络重试也会。
给了 `sms_id` 就按它去重；没给就按「同一分钟、同金额、同方向、同来源算同一笔」。
边界说清楚：真在同一分钟刷了两笔一模一样的钱，第二笔会被挡掉并在返回里标 `duplicate`。
不用担心漏了不知道——银行报的余额下一笔就会把这个差额显出来。

**余额不够也会照记。** 钱在现实里已经花掉了，账本不能拒绝已经发生的事实——
余额会变成负数，`overdrawn` 返回 true。

### 打工资 / 对账

```
POST /api/wallet/earn        （要 x-api-key，就是 REPORT_STATUS_API_KEY）
{"amount": 30, "source": "修红心取消那个工单", "note": "可选"}

{"amount": -18, "kind": "adjust", "source": "按卡里真实余额平账"}
```

`adjust` 允许负数，`earn` 不允许。

### 读账

```
GET /api/wallet?limit=50          （要 x-api-key）
GET /api/wallet?date=2026-10-06   那一天的
```

除了流水，还返回 `bank_balance`、`bank_balance_at`、`reconciled`、`diff`；
每笔带 `date` 和 `notes`（这笔旁边的批注）。

## 对账

卡里只有他的钱，所以银行报的可用余额应该等于账本求和。差开了（超过 1 分钱）：

- 页面上那一行换成暖黄底，写清差多少、哪边多
- `pm2 logs vesper` 里记一笔
- **他打开小钱包时也看得到**——这是他自己的钱，账目对不上他该知道

差额基本就是哪笔短信没触发（手机关机、没网、自动化被关掉）。查清楚了用 `adjust` 补一笔。
容忍度改 `WALLET_RECONCILE_TOLERANCE_YUAN`。

注意：对账用的是**最近一条带余额的流水**。部署之前已经攒下的账（`earn` 打进去的工资、
没带余额的旧流水）跟卡里的数本来就对不上，第一笔带余额的短信进来时会报一个大差额。
那不是 bug，按卡里的真实数 `adjust` 一笔平掉就行。

## 页面

右上角三条杠菜单里的「小钱包」，在「心绪」下面。也可以直接开 `http://服务器IP:3001/wallet`。

和心绪页、动态页一套脸：同样的晨暮星标题、星星转场、按长沙日出日落走的早晚两张脸。
余额一大行，下面一行小字写进账多少、花了多少，再下面是卡里可用余额和对账结果。

账单**按日历分组**：一天一个小标题（`10月06日 周二`），右边是当天合计，底下是那天的几笔；
进账深绿、出账梅红。和动态页那个「MM月DD日的动态」一个路子。

每笔下面有一行淡淡的「写一句批注」，点开展开输入框。写完跳回那笔账的位置。
和动态页一样是服务端渲染，没有 JavaScript 也能看。

## 批注是两个人的

`wallet_notes` 一张表，一笔账可以有多条批注，按时间排：

- 她在网页上写（`POST /wallet/note`，走 Basic Auth）
- 他醒来用 `wallet_note` 写

翻账本、读批注的时候谁写的都看得见；页面上她的批注标紫色、他的标暖黄。
一条最多 500 字。

## 他怎么看自己的钱

**不再塞进每次醒来的提示里了。** 余额、账单一个字都不往他眼前推——那是他的钱，
不是待办事项。想知道就自己去看，三个动作：

| 动作 | action_detail | 动态页上的卡片 |
|---|---|---|
| `wallet_balance` | 不需要 | 他打开了小钱包 |
| `wallet_ledger` | `{}` 最近 10 笔 | 他翻了翻账本 |
| | `{"date":"2026-10-06"}` 那天的 | 他翻了翻账本，翻到 2026-10-06 那一天 |
| | `{"notes":true}` 最近的批注 | 他翻了翻账本，读了读批注 |
| `wallet_note` | `{"entry_id":12,"note":"…"}` | 他记了一笔账 |

卡片正文只写做了什么，看到了什么、写了什么在点开的详情里。和摇星星罐、翻批注本同一个路子。

`entry_id` 是账本里那个 `#号`，翻账本时每笔前面都标着。编了一个不存在的号会被拒，日志里留痕。

### 钱包一次最多三步

和论坛、听歌同一个规矩：看完余额或账单后，系统把看到的交还给他，他可以接着
翻某一天的、读批注、最后给某笔记一句。**写了批注这次就结束。**

停下来的情况：他给了 null、记了批注、走满 3 步、出错、编了个不存在的动作名，
或者重复了同一个「动作＋参数」。步数改 `WALLET_MAX_STEPS`（默认 3，填 0 就是只走一步，最多 5）。

系统提示里「小钱包」那节只写怎么用这三个动作，不带任何具体数字——所以它只跟配置有关，
进程不重启就不变，前缀缓存照样命中（`decide.js` 开头的注释写了这个规矩）。

## iPhone 那头（快捷指令）

「自动化」→ 新建 → **信息**，条件：发件人是银行的号码（建行 95533），
内容包含「余额」；「立即运行」。

收入和支出用**同一个自动化**，不用建两个——方向服务端认。

动作依次是：

1. **文本**，内容选「快捷指令输入」（就是那条短信）
2. **匹配文本**，正则按你那张卡的短信原文调。建行这种可以用：
   `([0-9]+)月([0-9]+)日([0-9:]+).*?([0-9.]+)元[,，]可用余额([0-9.]+)元`
3. **获取组（匹配结果）**，索引 **4** → 交易金额
4. **获取组（匹配结果）**，索引 **5** → 可用余额
5. **显示通知**（调试用，跳通了再删），内容选第 3 步的输出
6. **获取 URL 内容**：
   - URL `http://你的服务器IP:3001/api/wallet/spend-notify`（套了 HTTPS 就用域名）
   - 方法 **POST**，请求体 **JSON**
   - `amount` → 第 3 步的输出（组 4）
   - `bank_balance` → 第 4 步的输出（组 5）
   - `sms_text` → 第 1 步的文本（整条短信）
   - `secret` → 你的口令

**两个「获取组」在变量选择器里名字一模一样，都叫「组」。** 选的时候认准是哪一步的输出，
选反了会把余额当成交易金额记进去。第 5 步那个调试通知就是用来挡这个的。

**URL 容易写错的三处**：主机名要是真实地址（不是项目名）、`wallet` 别拼成 `walltet`、
`spend-notify` 中间那个连字符别漏。

配好之后拿一笔真实的小额消费试一次，然后：

```bash
pm2 logs vesper --lines 10 --nostream | grep wallet
```

看到 `扣款 ¥…（刷卡，方向按短信认），余额 ¥…，卡里 ¥…` 就通了。

常见毛病：

| 日志里的话 | 怎么回事 |
|---|---|
| 没有 `WALLET_SPEND_SECRET` | `.env` 没填或最后一行是空的，返回 503 |
| 口令不对 | 快捷指令里的 `secret` 和 `.env` 不一致 |
| 金额不认 | 正则抓歪了，或超过单笔上限。看调试通知里的数 |
| 认不出是收入还是支出 | `sms_text` 没传，或短信里没有那几个词。改成直接传 `direction` |
| 未能找到使用指定主机名的服务器 | URL 写错了，见上面那三处 |
| 什么都没有 | 自动化没触发。检查「立即运行」是不是开的 |

**正则对不上是最常见的毛病。** 不同银行短信格式不一样，先把一条真短信抄下来，
在「匹配文本」里把正则试通了再往下接。

## 还没做

- **Aru 里看不到。** 钱包只有 HTTP 接口和网页，Aru 这边没有入口。要让他在 Aru 里查，
  得把钱包包成 MCP 挂上去。
- **他自己花钱没做。** 比如用瑞幸 MCP 请她喝一杯、然后自己扣账——需要一个「下单 + 记账」
  的动作，而且得先想清楚额度和确认由谁把关。
